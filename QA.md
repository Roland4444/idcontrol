# Изменения и проверка v0.6.4

- Исправлен разбор ответа VibeCode: берётся обычный текст из `choices[0].message.content`, JSON-таблица не ожидается.
- TIFF/BMP/GIF отправляются в Base64 **без перекодирования** под совместимым с тестом `data:image/jpeg`. PNG/JPEG напрямую, по собственным MIME.
- PDF **никогда** не передаётся как PDF-файл: Hayro рендерит страницы в JPEG внутри Rust, далее отдельные вызовы VibeCode.
- Добавлены офлайн unit-тесты для обработки текста, ошибок API, MIME и PDF из двух страниц.
- Проверка APP_PASSWORD: **не меньше 3 байт**, не начинается на CHANGE/REPLACE. 16 не возвращать.
- ZIP и справочники проверяются при упаковке. Rust-компилятор в окружении сборки архива отсутствует; реальная компиляция, ответ API и PDF-рендер не проверены.

# QA / проверка пилотной версии v0.6

## Статически проверяется при упаковке

- Сохранение кода DSM HTTPS с запретом mutating File Station API.
- Отдельная локальная PostgreSQL, пять последовательных SQLx-миграций.
- JSON-провайдер GigaChat по документированным OAuth/chat endpoints.
- GigaCowork только через корпоративный gateway собственного контракта.
- Дефолт `AI_MODE=off`, ручное согласие на комплект, только человек подтверждает предложение.
- Привязка всех ответов модели к конкретным ID документов и точным исходным цитатам.
- Каталоги: 14 видов работ, 169 позиций ИД, 34 типовые ошибки.

## Не проверено без стенда

- `cargo check`, `cargo test`, `cargo build`: в рабочем окружении сборки нет Rust toolchain.
- Связь с реальной Synology DSM и файлообмен по корпоративному TLS.
- Выполнение SQL-миграций на PostgreSQL, включая обновление существующей v0.5.
- Работоспособность авторизации/модели в учётной записи GigaChat конкретного тарифа.
- Интеграция с настоящим GigaCowork (публичный API не подтверждён).
- Производительность распознавания, безопасность/нагрузка, нормативная приемка.

## Обязательные тесты до эксплуатации

1. `cargo fmt --all -- --check`, `cargo check`, `cargo test`, `cargo build --release`.
2. На новой тестовой PostgreSQL применить миграции, проверить `_sqlx_migrations`.
3. Восстановить копию v0.5 и проверить обновление и сохранность истории.
4. Отключить NAS и убедиться, что файлы не удаляются из локального архива.
5. Негативный тест: неверная TLS-цепочка DSM отклоняется.
6. В `AI_MODE=off` проверить отсутствие исходящего запроса к облакам.
7. Включить `AI_MODE=cowork_gateway` с mock на localhost и проверить создание задания.
8. Включить `AI_MODE=gigachat` только после согласования внешней передачи.
9. Ответ провайдера с неверными ID или отсутствующими цитатами должен быть отброшен.
10. Проверить, что никакой ответ модели не изменяет оригиналы на NAS и не создаёт автоматически нормативное заключение.

### v0.6.2: изменение минимальной длины APP_PASSWORD
- Проверка в `src/config.rs`: `if password.len()<3 || password.starts_with("REPLACE") || password.starts_with("CHANGE") {`.
- Минимальная длина — 3 байта UTF-8 (`String::len()`), строки с префиксами `REPLACE` и `CHANGE` отвергаются.
- Другие компоненты не менялись; компиляция на Ubuntu/Windows требует локального `cargo check`.
