# Контроль ИД 0.6.8 — локальные каталоги Windows

Это **Windows-проект**: Python, Docker, Linux-папки `/var` или `/tmp` для локального хранилища не требуются.

## Рекомендуемый `.env` (рядом с Cargo.toml)

```dotenv
DATA_ROOT=./storage
TEMP_ROOT=./storage/temp
LOCAL_OCR_MODEL_DIR=./models/ocr
OCR_MODE=local
OCR_PAGE_WORKERS=6
OCR_MAX_PAGES=500
```

Пути с префиксом `./` вычисляются от папки файла `.env`, а не от текущего рабочего каталога. Например, если проект расположен в `C:\Users\user\Documents\rust\id-control-axum`, данные будут в `...\id-control-axum\storage`, временные файлы в `...\id-control-axum\storage\temp`, ONNX-модели — в `...\id-control-axum\models\ocr`.

Приложение создаёт папки автоматически. Пути выводятся при запуске в лог `Local Windows/project storage paths resolved`.

* `storage/originals`: локальные копии документов (не временные!), на которые ссылается PostgreSQL.
* `storage/inbox`: приём файлов из веб-интерфейса.
* `storage/temp`: временные папки скачивания с NAS и формирования PDF-отчётов. Временные папки автоматически удаляются после завершения задачи.

При установке в другую папку Windows не требуется изменять перечисленные относительные пути.

## Особое внимание: уже существующие документы и PostgreSQL

Если прежний `.env` содержал `DATA_ROOT=/var/lib/id-control` и архив уже заполнен, **не меняйте корневой путь вслепую**: прежние абсолютные пути к файлам сохранены в `documents.archive_path` PostgreSQL. Изменение только `.env` не перемещает файлы и не переписывает записи БД. Старые файлы при этом НЕ удаляются, но интерфейс может перестать их скачивать.

Перед миграцией: остановите сервер, сохраните копию PostgreSQL и архивной папки. Выясните, куда Windows фактически записала старый путь, и убедитесь, что в новой `storage/originals` файлы скопированы с той же структурой. Далее нужно аккуратно обновить пути в `documents.archive_path` на новую папку. Не выполняйте массовый SQL REPLACE без проверки точных старого и нового префиксов. Если архив ещё пуст, можно просто поставить новые параметры выше.

Windows-версия сразу остановится с понятной ошибкой, если в `.env` задано `DATA_ROOT=/var/...` или `TEMP_ROOT=/var/...`, чтобы не создавать случайно папку `C:\var`.

**Внимание:** `TEMP_ROOT` добавлен для реальных временных файлов сканера Synology и генерации отчётов. `DATA_ROOT` — долговременный локальный архив. Разделение намеренно.

## Проверка из PowerShell

```powershell
cargo check
cargo test
cargo run -- --check-local-models
cargo run
```

В начале лога должны появиться абсолютные пути `data_root=...\storage`, `temp_root=...\storage\temp`, `models=...\models\ocr`.

База PostgreSQL в WSL2 и содержимое Synology от этой настройки не меняются. Дополнительных SQL-миграций нет.
