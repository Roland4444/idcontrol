# Контроль ИД v0.9.5 — интерфейс по макетам и встраивание в Bitrix24

Разработка на основе исходного `id-control-axum.7z`, без разделения на сервисы и RabbitMQ. Обновлены шесть карточек ЖК с изображениями из сообщения пользователя, меню выбора, карточки 14 видов работ с уникальными SVG, назначения сотрудникам, представление загрузки/документов/замечаний/истории и выделение активной вкладки верхнего меню. Сохранены PostgreSQL, сканер Synology, локальный OCR и существующие проверки. Обновлены cookie для iframe (Partitioned) и добавлены проверки ID суперадминистраторов.

**Режим Bitrix24:** серверное локальное приложение открывается по `https://YOUR-APP-DOMAIN/bitrix`; нужны `BITRIX_DOMAIN` и права `user`. Rust проверяет временный `access_token` самостоятельно через `user.current`, затем создаёт серверную сессию. ID 1 и 336 получают права супер-администраторов. Администраторы проектов назначаются из вкладки «Администрирование».

**Режим отладки:** `cargo run -- --debug-login`, далее `http://127.0.0.1:8090` и Basic `admin` / `super123`. Отладочный режим разрешён только на loopback. Существующая БД и `.env` по-прежнему требуются; namespace отладки `debug` не смешивается с Bitrix24 ACL.

Инструкция обновления, настройки Bitrix24 и ограничения: **[docs/RELEASE_V095_BITRIX_UI_RU.md](docs/RELEASE_V095_BITRIX_UI_RU.md)**.

> Эта версия меняет интерфейс и авторизацию, но **не добавляет полноценный редактор орфографии/грамматики и не переписывает исходные DOCX/PDF на Synology**. Полная автоматическая корректура файлов и достоверная сверка каждого пункта НТД — отдельные функциональные этапы; не следует считать их готовыми.

# Основа проекта v0.6 — Rust/Axum + PostgreSQL + Synology HTTPS + гибридный ИИ

**Статус:** исходники пилотного MVP, промышленное внедрение после компиляции, тестов и инженерной валидации. Оригиналы Synology не изменяются. Отдельного публичного IP не требуется.

## Архитектура

```text
Synology DSM HTTPS:5001 / File Station API (read-only)
          |
          v
Rust + Axum + OCR на Ubuntu --------> локальные правила ГОСТ/СП (утверждает инженер)
          |                                |
          v                                v
PostgreSQL (local)               реестр замечаний, отчёты
          |
          +----> AI_MODE=off             (по умолчанию)
          +----> AI_MODE=gigachat        (официальный GigaChat REST API)
          +----> AI_MODE=cowork_gateway  (будущий собственный адаптер для GigaCowork)
                       |
                       v
              Черновые предложения ИИ → подтверждение инженером
```

## Особенности

- Прямая авторизация DSM/File Station HTTPS, сканирование только `SYNOLOGY_ROOT`.
- Проекты и комплекты создаются **во внутренней PostgreSQL**, не в Битрикс24.
- Форматы: PDF, DOCX, XLSX, JPG, PNG, TIFF, WebP. DWG/DXF в первом этапе не поддерживаются.
- 14 видов работ, 169 пунктов состава ИД, 34 типовые ошибки по исходному ТЗ (в `catalog/`).
- Нормативные правила создаются/утверждаются в интерфейсе. Совпадение ключевой фразы НЕ является заключением о нормативном соответствии.
- История версий документов, SHA-256, реестр замечаний, отчёты XLSX/DOCX/PDF.
- ИИ не исправляет фактические сведения и не изменяет DOCX: сравнивает отрывки ID и REFERENCE и предлагает проверяемые инженером замечания, а не юридически значимые заключения.
- Только ручной запуск внешнего ИИ после разрешения на уровне комплекта (`ai_consent`). Историю ИИ хранят `ai_jobs`, `ai_suggestions`.

## Запуск

Полная инструкция установки PostgreSQL, Ubuntu, миграций, systemd, Synology, Nginx: **`INSTALL_UBUNTU_HYBRID_RU.md`**.

```bash
cp .env.example .env
# Заполните DATABASE_URL, APP_PASSWORD, SYNOLOGY_URL, SYNOLOGY_ROOT и учётные данные
cargo fmt --all -- --check
cargo check
cargo test
cargo build --release
./target/release/id-control-axum --migrate-only
./target/release/id-control-axum --check-synology
./target/release/id-control-axum
```

`--migrate-only` применяет версионированные миграции через SQLx, не запуская сканер. Для CLI нужны те же параметры в `.env`. В production systemd выполняет этот шаг при старте автоматически.

## Интеграция с ИИ

- `docs/AI_INTEGRATION_RU.md` — GigaChat, включение/отключение, безопасности и ограничения.

## Миграции

`001_init.sql` → `002_norms.sql` → `003_norm_patterns.sql` → `004_synology_index.sql` → `005_ai_hybrid.sql`.

Таблица `_sqlx_migrations` управляет версиями. Перед обновлением с v0.5 сделайте `pg_dump -Fc` и проверьте обновление на тестовой копии базы.

## Чего пока нет

Автономного ИИ-агента с произвольными инструментами; прямой реализации API GigaCowork; настоящего подключения к Битрикс24; полноценных RBAC по проектам; графического сравнения чертежей; гарантированной проверки всех пунктов ГОСТ. Это отдельные этапы.


## v0.6.1: папки ПД и ИД непосредственно в корне Synology

Поддерживаются три варианта: `SYNOLOGY_ROOT/ПД|ИД/файл`,
`SYNOLOGY_ROOT/Проект/ПД|ИД/файл`,
`SYNOLOGY_ROOT/Проект/Вид работ/ПД|ИД/файл`.
В первом варианте локальное имя проекта задаётся `SYNOLOGY_PROJECT_NAME`
(по умолчанию имя последней папки SYNOLOGY_ROOT), а комплект создаётся
с именем `SYNOLOGY_DEFAULT_WORK` (по умолчанию `Вид работ не указан`).
Утвердите вид работ в интерфейсе перед нормативной проверкой комплектности.
Папка `ПД` равнозначна `ПД-РД`, `ИД` распознаётся без изменений.

Диагностика из Windows VS Code: `cargo run -- --list-synology`.
Команда выводит пути до 50 обнаруженных файлов без скачивания и доступа к PostgreSQL.
Сканер теперь логирует количество найденных и пропущенных файлов с причинами.
