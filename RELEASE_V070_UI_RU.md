# Контроль ИД v0.7.0 — интерфейс ПТО, вложения, чек-листы

## Изменения

- Сводка в начале страницы комплекта: количество документов, покрытие обязательных позиций, нерешённые замечания, документы без привязки. Процент — **покрытие чек-листа**, не процент соответствия строительным нормам.
- Кликабельные переходы на группы проверок, документов, OCR, настроек ИИ. Таблицы свёрнуты в раскрываемые блоки; раздел замечаний открыт по умолчанию.
- После ручного присвоения типа появляется подтверждение сохранения, страница прокручивается к изменённому файлу.
- `multiple`-загрузка до 20 файлов одним действием. Можно указать одну позицию чек-листа для всех загружаемых файлов; каждый файл хранится как самостоятельный документ/версия.
- Добавление, изменение названия, обязательности, примечания и скрытие собственных пунктов чек-листа для **конкретного комплекта**, не меняя общий каталог 169 позиций.
- ПД/РД запрещено передавать во внешние ИИ: классификационные задания ставятся только для ID, при OCR REFERENCE всегда используется локальный режим. Гибридное внешнее сравнение ИД с ПД/РД отключено до разработки локальной реализации.

## Обновление на Windows

1. Остановите приложение через Ctrl+C.
2. **НЕ удаляйте старую папку проекта.** Распакуйте ZIP поверх неё, сохранив собственные `.env`, `models\ocr`, `storage`, `Cargo.lock` при желании.
3. В архиве отсутствуют `models/`, `.env`, `storage/` и `Cargo.lock`. Его распаковка сама по себе не очищает эти каталоги.
4. Проверьте `DATA_ROOT=./storage`, `LOCAL_OCR_MODEL_DIR=./models/ocr` в вашем `.env`. Путь DATA_ROOT нельзя менять для существующей базы без переноса архива.
5. Выполните `cargo check`, затем `cargo test`, затем `cargo run`.
6. SQLx автоматически применит миграцию `008_checklist_ui.sql`. Не удаляйте существующую БД.
7. Откройте страницу комплекта. Первая карточка — сводка. Добавление файлов и редактирование чек-листа — через соответствующие раскрывающиеся разделы.

## Ограничения

- На этом этапе **нет персональных учётных записей и назначения сотрудников**: приложение продолжает использовать общий Basic Auth. Настоящий режим «Мои работы» потребует внедрения пользователей/прав и серверного ACL. Нельзя делать только CSS-фильтр чужих проектов.
- Редактирование стандартного чек-листа означает выбор обязательных позиций из каталога; сами общие позиции каталога не переименовываются. Собственные пункты разрешено изменять в каждом комплекте.
- Множественная загрузка синхронная, поскольку существующий pipeline `scanner::ingest` извлекает текст в ходе приёма. Большие файлы могут удерживать HTTP-запрос. Это следующая задача — перевод загрузки в фоновую очередь.
- Внешний GigaCowork по-прежнему требует отдельно развернутого адаптера; публичный API не подтверждён.
- Не выполнены нагрузочные и сквозные тесты на реальной Windows/SQLx/ONNX-среде — начать с `cargo check`.

## Защита исходников

Проверка `APP_PASSWORD`: `password.len()<3 || password.starts_with("REPLACE") || password.starts_with("CHANGE")` — не возвращайте лимит 16.
