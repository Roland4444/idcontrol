# ИИ-режимы и безопасные границы

## Режимы

1. `AI_MODE=off` (по умолчанию): документы остаются внутри компании, выполняются OCR, каталог ИД и локальные утверждённые нормативные правила. Никаких внешних ИИ-вызовов.
2. `AI_MODE=gigachat`: прямой HTTPS-вызов **официального GigaChat API**, не GigaCowork. Auth POST `https://ngw.devices.sberbank.ru:9443/api/v2/oauth` с заголовками `Authorization: Basic <ключ>`, `RqUID: UUIDv4`, form `scope=GIGACHAT_API_B2B` или иной выделенный организации scope. Далее Bearer token на `https://api.giga.chat/v1/chat/completions`. Выбранную модель необходимо проверить по тарифу и `GET /v1/models`.
3. `AI_MODE=cowork_gateway`: исходящий запрос на **наш собственный шлюз** (см. `COWORK_GATEWAY_CONTRACT.md`). Подключение самого шлюза к GigaCowork станет возможным только после получения разрешённого документированного способа интеграции у поставщика.

Документация Сбера:
- https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api
- https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token
- https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-chat
- https://test.cowork.ru/docs/GigaCowork/26.7.1/connectors_auth.html (общая документация коннекторов, **не REST API вызова агента**)

## Безопасный сценарий

- В таблице `packages` поле `ai_consent` по умолчанию `false`. Пользователь авторизуется, открывает комплект и явно включает разрешение. Изменение сохраняется в `audit`.
- Запуск ИИ-проверки только вручную, через форму с CSRF-токеном. Synology scanner не включает ИИ.
- В модель отправляется не более `AI_MAX_DOCS` (2–12) документов и не более `AI_MAX_CHARS_PER_DOC` (256–12000) символов распознанного текста каждого. По умолчанию до 6 документов × 4000 символов. **Не покрывает весь комплект**, если текст обрезан.
- Отправляются ИД и эталон ПД/РД только с нормальным статусом распознавания. Внешний ИИ получает строки с содержанием документов; редактирование и маскирование персональных данных дополнительно НЕ реализованы. До включения оцените применимые ограничения обработки/передачи.
- Движок Rust отвергает предложения со ссылкой на отсутствующие ID и цитаты, которых нет в переданном контексте. Но совпадение цитаты НЕ означает истинность вывода.
- ИИ не задаёт ГОСТ/СП/допуски и не пишет данные напрямую в `findings`. Его ответы в `ai_suggestions` (черновики). Подтверждение/отклонение инженером обязательно.
- Нет агента с автономным изменением DOCX, файла NAS, PostgreSQL или созданием задач в Битрикс24. Это намеренное ограничение пилота.
- Учётная запись Synology имеет только чтение. Оригиналы архивируются по SHA-256.

## Дополнительные мероприятия до промышленной эксплуатации

RBAC пользователей и доступ к проектам, полноценный CSRF/сессии вместо базовой авторизации, проверка актуальности НТД, работа со сканами и чертежами, защита ключей в secret manager, ограничение исходящих адресов, TLS PKI, резервные копии, определение сроков хранения, DLP/редакция персональных данных, тестирование модели на заведомо неправильных/правильных комплектах.
