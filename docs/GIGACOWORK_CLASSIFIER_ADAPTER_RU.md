# Контракт ИИ-классификатора: VibeCode / GigaCowork

## Что реально подключено

**Bitrix VibeCode**: прямой запрос `POST https://vibecode.bitrix24.tech/v1/ai/chat/completions` с `X-Api-Key` и `messages`, точно как в проверенном пользователем Rust-тесте. Отправляется **только текст OCR** с именем файла, а не оригинальный PDF или картинка. При `OCR_MODE=local` OCR остаётся локальным, независимо от того, какую модель выбрали в интерфейсе.

**GigaCowork**: на момент подготовки исходников подтверждённого публичного REST API сервиса GigaCowork с контрактом классификации документов нет. **GigaChat API — другой продукт, его нельзя молча выдавать за GigaCowork.** Поэтому переключатель GigaCowork выполняет запрос к вашему внешнему корпоративному адаптеру, URL которого задаётся `CLASSIFY_COWORK_URL`. Без него провайдер показывается как «не настроен», а его кнопки запуска недоступны. Не указывайте вымышленный адрес `gigacowork`.

Официальный API GigaChat (это не GigaCowork): https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api

## Подключение в Windows

Ничего не заменять в локальном `.env`, только добавить значения:

```dotenv
OCR_MODE=local
LOCAL_OCR_MODEL_DIR=./models/ocr
DATA_ROOT=./storage
TEMP_ROOT=./storage/temp
# ключ из уже рабочего пользовательского теста
VIBE_OCR_KEY=YOUR_KEY
CLASSIFY_VIBE_MODEL=
CLASSIFY_TIMEOUT_SECONDS=120
CLASSIFY_MAX_CHARS=8000
# только если разработан/согласован ваш адаптер GigaCowork
# CLASSIFY_COWORK_URL=https://your-ai-adapter.example.local/classify
# CLASSIFY_COWORK_TOKEN=YOUR_TOKEN
```

Не изменять пароль БД и `APP_PASSWORD`. Текущая проверка пароля остаётся `password.len()<3`.

1. Остановить прежний сервер через `Ctrl+C`, сделать резервную копию `.env` и базы PostgreSQL.
2. Обновлять **исходники в существующем каталоге проекта**, не удаляя папку. Не извлекать архив в новую папку вместо старой базы и архива.
3. Проверить `cargo check` и `cargo test`, затем `cargo run`. Миграция `007_ai_classification.sql` применяется автоматически через SQLx.
4. На странице комплекта ИД в блоке «Гибридный ИИ-анализ» поставить согласие на внешнюю передачу текстовых выдержек.
5. В новом блоке «ИИ-классификация документов» выбрать Bitrix VibeCode или GigaCowork и сохранить. При желании включить автопостановку после OCR.
6. Нажать «Классифицировать неопределённые», «Переклассифицировать все» либо действие у отдельного документа. Ожидать завершения; очередь обновляется каждые 5 секунд.
7. Перезагрузить страницу и нажать «Подтвердить тип ИИ» или «Отклонить» рядом с результатом. Пока не подтверждено, результаты ИИ не подменяют тип, определённый инженером.

При выборе провайдера **уже поставленные в очередь задания продолжаются со своим сохранённым провайдером**; для смены провайдера поставьте новые задания. Фоновая очередь классификации отделена от очереди OCR и от модуля нормативных проверок. На автоматическую отправку требуется и автопостановка, и `ai_consent=true` у комплекта, и настроенный выбранный провайдер.

## Формат адаптера GigaCowork

Приложение посылает `POST` JSON с `Authorization: Bearer <CLASSIFY_COWORK_TOKEN>` при настройке токена. **Это наш внутренний формат, не документированный API GigaCowork.**

```json
{
  "task": "classify_construction_document_v1",
  "instruction": "Текст инструкции классификатора",
  "document": {
    "filename": "ИД/Акт_15.pdf",
    "recognized_text": "Акт освидетельствования скрытых работ № 15 ...",
    "text_truncated": false
  }
}
```

Ожидаемый ответ адаптера (также допустимо обернуть объект в ключ `classification`):

```json
{
  "document_type": "Акт освидетельствования скрытых работ (АОСР)",
  "category": "Акты",
  "confidence": 0.94,
  "explanation": "В тексте есть соответствующий заголовок и состав комиссии",
  "evidence": ["Акт освидетельствования скрытых работ"],
  "document_number": "15",
  "document_date": null,
  "work_type": null
}
```

Ошибки HTTP, отсутствие `choices[0].message.content` у VibeCode и ошибки JSON показываются в очереди заданий в вебе и в консольных логах. Текст документа и ключи не пишутся в журнал. Входные цитаты проверяются на дословное вхождение в переданную выдержку и показываются рядом с предложением. Уверенность модели — оценка самой модели, не аттестация точности.

## Безопасность и ограничения

- Внешним моделям отправляется максимум `CLASSIFY_MAX_CHARS` символов OCR-текста (по умолчанию 8000) плюс имя файла. Может содержать ПД, персональные данные: проверяйте законность и договорные основания передачи.
- В документах могут быть инструкции, направленные против модели. Модель получает строгий системный промпт и документы отдельно как недоверенные данные; результат не исполняется.
- Ответ проверяется как JSON и сохраняется только как **предложение**. Подтверждение инженером требуется для изменения `documents.document_type` и связанного кода каталога.
- Подтверждённые человеком или вручную исправленные результаты не перезаписываются в ходе очередной классификации.
- Не отправляются исходные байты документов и не изменяется Synology. Локальный ONNX OCR по-прежнему использует модели из **локального каталога**, который не входит в ZIP.

## Тестирование

```
cargo check
cargo test
cargo run
```

Встроенные тесты `src/classification.rs` проверяют разбор JSON и ограничения на значения. Поскольку реальные ключи и доступ к сервисам не входят в архив, интеграционное тестирование с VibeCode и GigaCowork нужно провести на вашей рабочей Windows-машине.
