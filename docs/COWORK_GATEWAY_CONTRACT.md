# Предварительный контракт внутреннего шлюза GigaCowork

**Важно:** ЭТО НАШ СОБСТВЕННЫЙ КОНТРАКТ. Это не документация и не обещание наличия API GigaCowork. Прямой публично документированный метод создания задач в GigaCowork не подтверждён. Пока поставщик не предоставит контракт, используйте `AI_MODE=off` либо официальный `AI_MODE=gigachat`.

Когда станет известна подтверждённая схема интеграции, достаточно реализовать шлюз, который принимает HTTP POST по `AI_GATEWAY_URL` и обращается к подтверждённому API GigaCowork. Вся остальная система (Synology, PostgreSQL, проверки и UI) при этом не меняется.

## Запрос

`POST /v1/document-review`, `Content-Type: application/json`, опционально `Authorization: Bearer <AI_GATEWAY_TOKEN>`.

```json
{
  "instruction": "...проверить возможные смысловые расхождения, не утверждать нормы...",
  "documents": [
    {"id": 205, "kind": "ID", "name": "ИД/АОСР-15.docx", "content": "Бетон класса В20..."},
    {"id": 101, "kind": "REFERENCE", "name": "REFERENCE/РД.pdf", "content": "Бетон класса В25..."}
  ],
  "truncated": true
}
```

## Ответ

```json
{
  "suggestions": [
    {
      "document_id": 205,
      "reference_document_id": 101,
      "source_quote": "Бетон класса В20",
      "reference_quote": "Бетон класса В25",
      "description": "В исполнительной и рабочей документации различаются указанные классы бетона.",
      "proposed_action": "Инженеру проверить фактический материал и наличие согласованного изменения ПД/РД.",
      "confidence": 0.83
    }
  ]
}
```

Правила валидации на стороне Rust: число предложений не больше 8; идентификаторы принадлежат полученным файлам этого комплекта; исходный документ типа `ID`, эталон типа `REFERENCE`; обе цитаты точно присутствуют в переданных фрагментах; размеры полей ограничены; отсутствие текста или эталона — ошибка, а не соответствие. Результаты попадают **только в черновые предложения** `ai_suggestions`, которые подтверждает человек.

### Как протестировать контракт без внешнего ИИ

```bash
cargo run --example gateway_mock
```

Во втором терминале установите в `.env`:

```dotenv
AI_MODE=cowork_gateway
AI_GATEWAY_URL=http://127.0.0.1:9011/v1/document-review
```

Mock сервер всегда возвращает пустой массив `suggestions`. Он только тестирует транспорт и не проверяет документы. Для реального подключения установить `https://...` шлюз, TLS-сертификат, контроль доступа, журнал аудита, договор/разрешение на обработку данных. Не подставляйте адрес веб-сайта GigaCowork вместо API-шлюза.
