# Контроль ИД v0.9.2 — автоматический вход через Bitrix24 по образцу калькулятора

Единое приложение Rust + Axum, без Phoenix и RabbitMQ. Никаких вручную получаемых OAuth-токенов, ключей доступа сотрудников и отдельных паролей для входа через Bitrix24.

## Как проходит вход

1. Битрикс24 открывает серверную страницу `https://idai.kenreskenres7772023777.netcraze.link/bitrix` во встроенном iframe (GET или POST).
2. `BX24.init()` и `BX24.callMethod('user.current')` получают информацию о сотруднике для отображения. При установке отдельный `BX24.install()` вызывает `BX24.installFinish()`.
3. `BX24.getAuth()` автоматически возвращает действующие краткосрочные данные авторизации приложения. SDK делает это сам; сотрудник и администратор никаких токенов вручную не копируют. В Rust отправляются только временное `access_token` и `domain`; **никакой `user_id`/`member_id` от браузера для авторизации не принимается**.
4. Rust обращается по HTTPS к `https://BITRIX_DOMAIN/rest/user.current.json` с этими временными данными, получает подтверждённый Bitrix24 `ID` и создаёт серверную сессию.
5. Сессия записывается в PostgreSQL (`portal_sessions`, SHA-256 от случайного ключа) и выдаётся браузеру в cookie `__Host-idcontrol_session` (`Secure; HttpOnly; SameSite=None`, 6 часов). Роль и доступ к ЖК/пакетам проверяются сервером по подтверждённому ID.

`BITRIX_DOMAIN` **обязателен** только потому, что backend должен иметь доверенный адрес портала, а не принимать произвольный адрес от браузера. Он не является токеном.

## Конфигурация на Ubuntu cloud

Оставь существующий `.env`, `models/ocr`, `storage` и PostgreSQL без изменений. В `.env` достаточно:

```dotenv
BITRIX_DOMAIN=ваш_портал.bitrix24.ru
LISTEN=127.0.0.1:8090
```

Указывай настоящий домен портала, без `https://` и завершающего `/`.

`BITRIX_MEMBER_ID` **теперь необязателен**. В новой установке пространство пользовательских прав автоматически обозначается как `portal:ваш_портал.bitrix24.ru`. Если в v0.9.1 уже назначали сотрудников, сохрани **ранее заданное** `BITRIX_MEMBER_ID`, чтобы существующие записи ACL остались доступны. Нельзя подставлять в него ID человека. Для новых установок эту переменную можно полностью убрать.

Запуск:

```bash
cd ~/rust/idcontrol
cargo check
cargo run -- --migrate-only
cargo run
```

Если приложение запускается через systemd — перезапусти его службу вместо второго `cargo run`.

Прямой URL `/` без сессии должен возвращать 401, а `/bitrix` открывать страницу подключения, входя непосредственно из Битрикс24. Подтверждённый сотрудник `1` или `336` имеет права супер-администратора, остальные права задаются назначениями в PostgreSQL.

Отладка (только на изолированной машине, не на публичном домене):

```bash
cargo run -- --debug-login
```

Логин `admin`, пароль `super123`. В обычном режиме они не работают.

## Важные замечания

- OAuth как протокол обмена с Битрикс24 технически присутствует, но **человеку не нужно вручную получать или вводить токены**. `BX24.getAuth()` отдаёт их из текущей сессии автоматически, сервер использует их только для `user.current` и не хранит их в PostgreSQL.
- На входе `/auth/bitrix` нельзя верить полю `user_id`, переданному клиентом. В новой версии поле не предусмотрено. `member_id` также не используется как клиентский ключ доступа.
- При запрете сторонних cookie браузером встроенный iframe может потерять сессию; режим first-party/Storage Access API в этом патче не реализован. В такой ситуации нужна отдельная доработка, а не передача ключа в URL.
- Пароль приложения проверяется в прежнем режиме `len() < 3`; требования 16 символов обратно не добавлялись.
- Nginx и Keenetic остаются без изменений: Keenetic HTTPS → Nginx HTTPS:443 → Rust:8090.
- Никаких новых миграций SQL в v0.9.2 нет, схемы PostgreSQL и пользовательские документы не тронуты.

## Что изменено

- `src/access.rs` — автоматический namespace RBAC от доверенного домена, независимая серверная проверка, без обязательного `BITRIX_MEMBER_ID`.
- `assets/bitrix-client.html` и `.js` — вызов `user.current` в стиле калькулятора, автоматическая проверка через backend, ошибки и установка.
- `.env.example`, `Cargo.toml`, документация.

## Проверка после обновления

1. `cargo check` без ошибок.
2. `cargo run -- --migrate-only` без ошибок.
3. В портале приложение открывается по `/bitrix` и перенаправляет на `/`.
4. `/api/me` возвращает правильный `id`.
5. ID 1/336 видят «Администрирование»; другой сотрудник без ACL не видит чужие работы.
6. `POST /auth/bitrix` без действительной сессии Битрикс24 возвращает 401; передача `user_id:1` в JSON не должна давать права.
7. Отсутствие cookie в iframe проявляется как повторный 401 после редиректа; проверь cookie-политику браузера.

Проверка компиляции и входа в настоящий портал выполняются на вашем `cloud`: в среде подготовки нет `cargo` и сетевого доступа к вашей PostgreSQL.
