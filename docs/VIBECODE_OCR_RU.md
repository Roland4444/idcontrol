# VibeCode OCR: Rust + Axum, версия 0.6.4

В этой версии обработчик построен **по подтверждённому пользователем примеру Rust**: `reqwest::Client`, заголовок `X-Api-Key`, `messages`, `image_url` с `data:...;base64,...`, а результат берётся из JSON-поля `choices[0].message.content` **как строка**. Строка с результатом НЕ разбирается повторно как JSON: ошибки вида `trailing characters at line 1 column 2` больше не возникают только из-за того, что ответ содержит обычный текст.

## Какие файлы и как передаются

| Формат | Порядок работы | Уточнения |
|---|---|---|
| JPG/JPEG | Оригинальные байты -> Base64 -> `data:image/jpeg` -> VibeCode | Без конвертации |
| PNG | Оригинальные байты -> Base64 -> `data:image/png` -> VibeCode | Без конвертации |
| TIFF/TIF | Оригинальные байты -> Base64 -> `data:image/jpeg` -> VibeCode | **Специально повторяет твой успешный тест**: URI сообщает JPEG, но байты содержат TIFF. Это нестандартное поведение, зависящее от VibeCode. Если провайдер изменит требования, потребуется другая схема. Многостраничные TIFF маркируются как `partial`, пока не доказана полнота OCR |
| BMP | Оригинальные байты -> Base64 -> `data:image/jpeg` -> VibeCode | Аналогично подтверждённому тесту |
| GIF | Оригинальные байты -> Base64 -> `data:image/jpeg` -> VibeCode | Аналогично подтверждённому тесту; многостраничность GIF не проверяется |
| WebP | Оригинальные байты -> Base64 -> `data:image/jpeg` -> VibeCode | Экспериментальная совместимость, не проверенная на твоём API |
| PDF | **НЕ отправлять PDF как image_url.** Открыть и отрисовать каждую страницу в **JPEG средствами Rust (`hayro`)**, затем по одной передать через VibeCode | Твой тест показал, что PDF напрямую не распознаётся. Метки `=== Страница N ===` сохраняют привязку к страницам. Из-за `OCR_MAX_PAGES` или ошибок отдельных страниц статус `partial`/`manual` |
| DOCX/XLSX | Извлечь текст локально (без VibeCode) | DOCX XML, XLSX calamine |

Никаких зависимостей от `pdftoppm`, `pdftotext`, Tesseract или LibreOffice для OCR больше нет. Возможны особые PDF, которые `hayro` не сможет открыть; ошибка будет явно указана. Для визуального OCR PDF страницы всё равно требуется **рендеринг** — просто уже не внешней программой.

## Конфигурация `.env`

```dotenv
VIBE_OCR_ENABLED=true
VIBE_OCR_URL=https://vibecode.bitrix24.tech/v1/ai/chat/completions
VIBE_OCR_KEY=ВАШ_КЛЮЧ
# Альтернатива ключу в .env:
# VIBE_OCR_KEY_FILE=KEY
# Оставь модель пустой, как в подтверждённом работающем примере.
VIBE_OCR_MODEL=
# 0 = не передавать max_tokens (совпадает с твоим примером).
VIBE_OCR_MAX_TOKENS=0
VIBE_OCR_TIMEOUT_SECONDS=120
OCR_MAX_PAGES=20
```

Для OCR не нужно включать `AI_MODE=gigachat`, он управляется `VIBE_OCR_ENABLED` независимо. Внешний сервис получает изображения (включая страницы PDF) и может обрабатывать содержащиеся в них персональные/коммерческие данные. Включай OCR только для разрешённых к передаче документов.

## Проверка на Windows PowerShell / VS Code

```powershell
cargo check
cargo test
cargo run -- --check-vibe-ocr "00.tif"
cargo run -- --check-vibe-ocr "1.bmp"
cargo run -- --check-vibe-ocr "1.gif"
cargo run -- --check-vibe-ocr "test.pdf"
```

В ходе проверки будет напечатано `Recognition status: ocr_vibe` и полный текст `EXTRACTED`. Путь к файлу может быть абсолютным. Для PDF будет один запрос **на каждую страницу**, из-за чего затраты времени и токенов выше.

После первого запуска можно повторить обработку уже сохранённых в PostgreSQL документов со старой ошибкой:

```powershell
# Остановить текущий сервер Ctrl+C; затем из каталога проекта:
cargo run -- --reprocess-errors
cargo run
```

`--reprocess-errors` обрабатывает записи со статусами `error:`, `manual`, `partial`, используя **локальные архивные оригиналы**: не меняет файлы на Synology, не создаёт дубликаты версий. Если ранее PDF получил статус `extracted`, но его надо повторно обработать, используй `--reprocess-all` (может привести к дополнительным расходам API).

## Отдельно о распознавании и проверке ГОСТ

Статус `ocr_vibe` означает лишь наличие текстового ответа API, а не его достоверность. VibeCode может неверно считать цифры, обозначения осей или типы материалов. Сравнение с ПД/РД, нормативные требования и заключение по соответствию — отдельные стадии. При неполной или сомнительной информации требуется инженерная проверка.

## Отказ API

- HTTP 401/403 — ключ или права к API.
- HTTP 429 — лимит/квота, выполняются ограниченные повторы.
- HTTP 400/415 — провайдер не принял формат изображения или параметры запроса.
- JSON с полем `error` — теперь показан текст ошибки провайдера (без дампа документа).
- `choices[0].message.content` не строка — теперь показывается точная диагностическая причина; `content`-массив с текстовыми частями также поддержан.

Не отправляй PDF напрямую в `image_url`, независимо от значения MIME. Проверку TLS для VibeCode не отключать.

**Важно:** пользователь запросил сохранять `if password.len()<3 || password.starts_with("REPLACE") || password.starts_with("CHANGE") {`. Это сохранено — в `APP_PASSWORD` нет проверки на 16 символов.
